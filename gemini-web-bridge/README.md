# gemini-web-bridge

Локальный прокси на FastAPI + uvicorn. Он принимает куки вашей авторизованной сессии
`gemini.google.com` (подписка Google AI Pro) и поднимает OpenAI-совместимый эндпоинт
`/v1/chat/completions` с поддержкой SSE-стриминга. Подключаться можно клиентами вроде
OpenCode, Roo Code и Aider.

## Как это устроено

- Протокол веб-приложения (`StreamGenerate`, токен `SNlM0e`, `_reqid`, `f.req`, заголовок выбора модели)
  реализует библиотека [`gemini-webapi`](https://pypi.org/project/gemini-webapi/) версии 2.1.1.
  Она же ротирует `__Secure-1PSIDTS` и подставляет актуальные идентификаторы моделей вашего аккаунта.
- Транспорт — `curl_cffi` (ставится вместе с библиотекой). Он отдаёт набор заголовков Chrome 145:
  `User-Agent`, `sec-ch-ua`, `sec-ch-ua-platform`, `sec-fetch-*`. Эти заголовки согласованы с TLS-отпечатком.
- Все запросы к веб-сессии идут строго по одному, с паузой 1.0–2.5 с (случайный jitter) между ними.
- Токен `SNlM0e` пересоздаётся каждые ~30 минут (±15%) и после каждой ошибки.
  `__Secure-1PSIDTS` обновляется библиотекой примерно раз в 10 минут. Ротированные куки хранятся
  в `.state/` с правами 700.

> **Важно.** Это неофициальный способ доступа. Он использует внутренний веб-протокол Google, а не
> публичный API. Такой доступ может противоречить условиям использования сервиса, а Google может
> в любой момент изменить протокол или отозвать сессию. Используйте его только со своим аккаунтом
> и для личных задач. Куки равноценны паролю от аккаунта: не коммитьте `.env`, не передавайте его
> другим и не открывайте порт прокси наружу без `BRIDGE_API_KEY`.

## Запуск

Требуется Python 3.11 или новее.

**1. Получите куки.** В браузере откройте `https://gemini.google.com` (вы должны быть залогинены),
нажмите F12 → вкладка **Application** (в Firefox — **Storage**) → **Cookies** → `https://gemini.google.com`.
Скопируйте значения `__Secure-1PSID` и `__Secure-1PSIDTS`.

**2. Запустите одной командой:**

```bash
cd gemini-web-bridge && ./run.sh
```

При первом запуске скрипт создаст `.env` из `.env.example` и остановится. Впишите в `.env`
`GEMINI_COOKIE_1PSID` и `GEMINI_COOKIE_1PSIDTS`, затем снова выполните `./run.sh`. Скрипт создаст
`.venv`, установит зависимости из `requirements.txt` и запустит сервер на `http://127.0.0.1:8000`.

Вручную то же самое делается так:

```bash
cd gemini-web-bridge
cp .env.example .env            # впишите куки
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python server.py
```

## Проверка через curl

```bash
# 1. Состояние сессии (200 — готово, 503 — куки не приняты или нет сети до Google)
curl -s http://127.0.0.1:8000/healthz

# 2. Список моделей
curl -s http://127.0.0.1:8000/v1/models

# 3. Обычный запрос
curl -s http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "gemini-2.5-pro", "messages": [{"role": "user", "content": "Ответь одним словом: привет?"}]}'

# 4. Потоковый ответ (SSE). -N отключает буферизацию curl
curl -N http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "gemini-2.5-pro", "stream": true, "messages": [
        {"role": "system", "content": "Отвечай кратко."},
        {"role": "user", "content": "Сколько будет 2+2?"},
        {"role": "assistant", "content": "4"},
        {"role": "user", "content": "А 3+3?"}]}'
```

Если задан `BRIDGE_API_KEY`, добавьте в каждый запрос `-H "Authorization: Bearer $BRIDGE_API_KEY"`.
`/healthz` ключа не требует.

Ответ стриминга выглядит так: кадры `data: {...chat.completion.chunk...}`, в конце `data: [DONE]`.

## Подключение клиентов

| Параметр | Значение |
| --- | --- |
| Base URL | `http://127.0.0.1:8000/v1` |
| API key | значение `BRIDGE_API_KEY` (если задан, иначе любая строка) |
| Model | `gemini-2.5-pro` (или любое имя из `/v1/models`) |
| Streaming | включено |

Aider, например:

```bash
OPENAI_API_BASE=http://127.0.0.1:8000/v1 OPENAI_API_KEY=local aider --model openai/gemini-2.5-pro
```

## Как сообщения превращаются в промпт

- Одиночное сообщение `user` без `system` отправляется как есть.
- Иначе история собирается в транскрипт: блок `### System instructions` (роли `system` и `developer`),
  затем реплики `User:`, `Assistant:`, `Tool result:` по порядку, и в конце подсказка `Assistant:`.
  Перед транскриптом стоит инструкция отвечать только на последнее сообщение пользователя.
- Каждый запрос идёт во временном чате (`GEMINI_TEMPORARY_CHAT=true`), поэтому он не засоряет историю Gemini.
  Контекст передаётся целиком в самом промпте.

## Tool calling (эмуляция function calling)

Веб-интерфейс Gemini не умеет вызывать инструменты через API, поэтому мост делает это сам: описания
функций передаются модели текстом, а её ответ разбирается обратно в `tool_calls`.

```
OpenAI-запрос (tools) -> инструкция в system-блоке промпта -> ответ Gemini -> разбор <tool_call> -> tool_calls
```

**Вход.** Если в запросе есть `tools`, имена, описания и JSON-схемы параметров внедряются в начало
системной инструкции. Модели велено вызывать функцию только так:

```
<tool_call>
{"name": "<имя_функции>", "arguments": {<json_аргументы>}}
</tool_call>
```

Поддерживаются `tool_choice`: `auto` (по умолчанию), `none` (инструменты отключены, блоки передаются
как текст), `required` (модель обязана вызвать одну из функций) и `{"type": "function", "function": {"name": ...}}`
(обязательный вызов конкретной функции, остальные скрываются).

**История.** Сообщения `role: "tool"` (и устаревший `role: "function"`) попадают в промпт как
`Tool Result (<tool_name> / <tool_call_id>): <content>`. Имя функции берётся из поля `name` или из
`tool_calls` предыдущего ответа assistant. Вызовы из `tool_calls` в истории переписываются в том же
блоке `<tool_call>`, так что модель видит свои прошлые вызовы в знакомом формате.

**Выход без стриминга (`stream: false`).** Текст разбирается по блокам `<tool_call>`. Валидные блоки
становятся элементами `tool_calls` с идентификаторами `call_<uuid>`, при этом `finish_reason` равен
`tool_calls`. Текст вне блоков остаётся в `content` (если его нет, то `content: null`).

**Выход со стримингом (`stream: true`).** Детектор буферизует вывод. Текст без тегов уходит сразу,
задерживаются только символы, которые могут быть началом `<tool_call>`. Содержимое блока копится до
`</tool_call>`, затем отправляется кадр с `delta.tool_calls`. В конце приходит кадр с
`finish_reason: "tool_calls"`. Если вызовов не было, поток идёт как обычные `delta.content` с `stop`.

**Ошибки модели.** Блок с невалидным JSON, неизвестным именем функции, неверным типом аргументов или
без обязательного параметра не роняет запрос: он возвращается клиенту обычным текстом в `content`
вместе с исходными тегами, и агент видит, что пошло не так, и может переспросить. Незакрытый блок до
конца ответа тоже возвращается текстом. Фрагменты в блоке, обёрнутые в ```` ```json ```` , принимаются.

**Ограничения эмуляции.** Качество зависит от модели: она может не придерживаться формата. Поэтому
сервер не гарантирует вызов функции даже при `tool_choice: "required"`. Аргументы не проверяются по
JSON Schema целиком: проверяется только, что они объект и содержат обязательные поля (`required`).

## Конфигурация

Все параметры задаются в `.env` (шаблон — `.env.example`):

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GEMINI_COOKIE_1PSID` | — | Обязательно. Куки `__Secure-1PSID` |
| `GEMINI_COOKIE_1PSIDTS` | — | Рекомендуется. Куки `__Secure-1PSIDTS` |
| `GEMINI_MODEL` | `gemini-2.5-pro` | Модель по умолчанию; сопоставляется с моделями аккаунта |
| `BRIDGE_API_KEY` | пусто | Ключ доступа к `/v1/*` |
| `HOST` / `PORT` | `127.0.0.1` / `8000` | Адрес и порт сервера |
| `GEMINI_PROXY` | пусто | Прокси для исходящих запросов к Google |
| `GEMINI_REQUEST_DELAY_MIN` / `_MAX` | `1.0` / `2.5` | Пауза между запросами к Gemini, секунды |
| `GEMINI_TOKEN_ROTATE_MINUTES` | `30` | Интервал пересоздания сессии и токена SNlM0e |
| `GEMINI_TEMPORARY_CHAT` | `true` | Не сохранять чаты в истории Gemini |
| `GEMINI_TIMEOUT` | `300` | Таймаут одного запроса, секунды |
| `GEMINI_COOKIE_PATH` | `.state/` | Каталог для ротированных кук |
| `LOG_LEVEL` | `INFO` | Уровень логов |

Если вы обновили куки в `.env`, удалите каталог `.state/`. Иначе библиотека использует сохранённые
ранее (и, возможно, более свежие) куки того же аккаунта.

## Ограничения

- **Изображения и файлы в сообщениях не поддерживаются.** Части `image_url` и т.п. возвращают 400.
- Параметры `temperature`, `max_tokens` и подобные принимаются, но игнорируются: веб-интерфейс Gemini их не даёт менять.
- Поле `usage` в ответах не заполняется.
- Запросы выполняются последовательно: параллельные запросы встают в очередь.
- Обход reCAPTCHA и других антибот-проверок **не реализован**. Если Google потребует проверку или
  ограничит доступ, прокси вернёт ошибку 429 или 502 с текстом причины.
- Заголовки Chrome задаёт штатный профиль `curl_cffi`, а не ручной код. Ручная подмена `User-Agent`
  без совпадения с TLS-отпечатком выглядит подозрительнее, чем согласованный профиль.

## Коды ошибок

| HTTP | Тип | Что делать |
| --- | --- | --- |
| 400 | `invalid_request_error` | Проверьте тело запроса, роли и типы содержимого |
| 401 | `invalid_api_key` | Передайте `Authorization: Bearer <BRIDGE_API_KEY>` |
| 401 | `authentication_error` | Куки отклонены: обновите их из свежей сессии и удалите `.state/` |
| 429 | `rate_limit_exceeded` | Лимит аккаунта исчерпан или доступ временно ограничен; подождите |
| 502 | `upstream_error` | Ошибка протокола или сети. Смотрите лог сервера |
| 503 | — (`/healthz`) | Сессия не открыта: проверьте куки, сеть и `last_error` |
| 504 | `timeout` | Gemini не ответил вовремя; увеличьте `GEMINI_TIMEOUT` |

Если ошибка происходит после начала стриминга, заголовки 200 уже отправлены. В этом случае ошибка
приходит кадром `data: {"error": {...}}`, после которого идёт `data: [DONE]`.

## Тесты

```bash
cd gemini-web-bridge
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest
```

Тесты не ходят в сеть: клиент Gemini подменён заглушкой. Они покрывают промпт, разбор `tools`,
детектор `<tool_call>` для обычного ответа и для стриминга, обработку ошибок и настройки.

## Файлы

- `server.py`: сервер, мост к веб-сессии и OpenAI-совместимый API.
- `requirements.txt`: зависимости.
- `requirements-dev.txt`, `pytest.ini`, `tests/`: зависимости и тесты.
- `.env.example`: шаблон настроек.
- `run.sh`: запуск одной командой.
- `.gitignore`: исключает `.env`, `.state/` и `.venv/`.
